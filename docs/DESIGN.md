# 技术设计 / Design Notes

本文说明为什么这个宏不是“按一下 ↓”，以及 1.0 为什么采用全角空格网格和改写模式。

## 问题

目标场景：

```text
先生と学生が話しています。
        ^ 光标在「学生」后面
```

按下快捷键后，希望：

```text
先生と学生が話しています。
            学生
            ^ 光标在下一行同一列
```

约束：

- 不能把「が話しています。」挤到下一行；
- 同一行可能要补写「先生」的注释（在「学生」左边）；
- 不能随意改动日文原文；
- 只在普通 Word 正文里工作。

## Word 对象模型的硬限制

Word 的普通文本不是固定网格编辑器：

1. 插入点只能停在**已有字符的边界**或段落标记处。
2. 空白段落没有“第 N 列”的插入点；它的起点由左缩进/首行缩进决定。
3. VBA 没有“把光标设置到任意像素/磅坐标”的 API，只能读取
   `Selection.Information(wdHorizontalPositionRelativeToTextBoundary)` 这类信息，再通过字符/格式间接定位。
4. 在光标处插入段落标记会拆分段落，后面的文字会进入新段落。

因此，纯“移动光标”无法把光标悬在真正的空白处。必须给目标行一个**锚点**。

## 方案比较

| 方案 | 优点 | 缺点 |
|---|---|---|
| 首行缩进 | 不增加字符；适合空行 | 只控制行首；一旦写入文字，行开始固定在第一次注释的列，左侧没有列可放光标；再次跳转会失败 |
| 制表位 + Tab | 精确到点 | Tab 只能跳到制表位；默认制表位会干扰；仍会插入字符 |
| 两行表格 | 最稳定；单元格互不影响；适合正式排版 | 需要预先按词/字符分列；不是“随时按快捷键”的工作流 |
| 文本框/形状 | 可任意定位 | 编辑体验差；多对象管理困难；打印/导出复杂 |
| 全角空格网格 + 改写 | 保留连续行工作流；任意列可用；无第三方依赖 | 注释行含大量不可见空格；依赖全角宽度；需要改写模式保护已有注释 |

1.0 选择最后一种。

## 1.0 算法

缩写：

- `x`：当前光标相对正文左边界的水平位置（磅）。
- `srcSize`：源文字字号（磅）。
- 网格行：由全角空格 `U+3000` 组成的注释段落。

步骤：

1. 关闭改写模式（避免在日文行误覆盖）。
2. 只在普通插入点、正文主故事、非表格中执行。
3. 读取 `x`、源字体名和字号。
4. 找到当前段落在 `Paragraphs` 集合中的位置：
   - 遍历 `doc.Paragraphs(i)`，比较 `Range.Start`；
   - **不能使用 `Paragraph.Index`**：Word 的 `Paragraph` 对象没有这个属性。
5. 取下一段：
   - 没有下一段：`curP.Range.InsertParagraphAfter`，新段落索引为 `curIdx + 1`；
   - 下一段为空：直接使用；
   - 下一段是网格行（包含至少 3 个全角空格）：直接使用；
   - 下一段是普通正文：在两者之间插入一条专用注释行；
   - 下一段是旧版首行缩进注释行：提示删除并退出。
6. 如果目标段为空，生成网格：
   - 段落对齐设为左对齐，左右缩进/首行缩进清零；
   - 字体设为源字体和源字号；
   - 按正文宽度除以字号，计算全角空格数量（留一列余量，避免换行）；
   - 用 `Range.InsertBefore` 插入全角空格。
7. 把光标移到目标段最接近 `x` 的字符边界：
   - 从段落起点开始逐字符 `MoveRight`；
   - 每次读取 `Information(7)`，记录差值最小的字符偏移；
   - 最后重新定位。逐字符测量兼容全角/半角混排，而不是简单按列数计算。
8. 如果目标行右侧存在非空格文字，打开 Word 的 `Options.Overtype`；否则关闭。
9. 状态栏给出“已定位”或“改写模式”提示。

## 为什么用全角空格

- 在日文字体（MS Mincho / MS Gothic 等）中，`U+3000` 的宽度为 `1em`，与一个全角假名/汉字/全角标点同宽。
- 源文本每前进一个全角字符，`x` 增加约一个字号；网格每前进一个全角空格，也增加一个字号，因此列可以对齐。
- 半角字符的宽度不是整数个 `em`，所以只保证“最接近的字符边界”，不保证半列精度。

## 为什么需要改写模式

假设注释行是：

```text
[空格×5]学生[空格×N]
```

要在「学生」左边补写「老师」：

- **插入模式**：在目标列插入「老师」，后面的空格和「学生」整体右移两个全角宽度，`学生` 不再对齐。
- **改写模式**：每输入一个全角字符，替换一个全角空格；行总长度基本不变，后面的「学生」保持原位。

因此宏在检测到右侧已有文字时自动切到改写。它不会强制在普通日文段落使用改写；每次宏开始也会先切回插入模式。

## 关键修复记录

### 4608

旧实现：

```vba
doc.Range(p.Range.End, p.Range.End).InsertAfter Chr(13)
```

在文档最后一个段落之后，这个 Range 位于文档边界，`InsertAfter` 触发 4608。修复：

```vba
curP.Range.InsertParagraphAfter
Set nextP = doc.Paragraphs(curIdx + 1)
```

### 438

旧实现使用 `curP.Index` 获取当前段落索引。Word 的 `Paragraph` 对象没有 `Index` 属性，运行时报 438。修复：

```vba
For i = 1 To doc.Paragraphs.Count
    If doc.Paragraphs(i).Range.Start = curP.Range.Start Then
        curIdx = i
        Exit For
    End If
Next i
```

### 第二次跳转失败

旧实现只对齐空段落；一旦用户写了内容，宏就跳过，导致第二次按快捷键没有反应。1.0 引入网格行识别（全角空格数量）和改写模式，支持同一行多个注释。

## 编码与分发

- `src/CaretDownAligned.bas`：ASCII、CRLF、`Attribute VB_Name = "CaretDownAlignedModule"`，可直接导入。
- `src/CaretDownAligned.zh-CN.vba.txt`：UTF-8（无 BOM），用于复制粘贴；不含 `Attribute` 行，避免粘贴到 VBA 编辑器时报语法错误。
- 为什么中文不直接做成 `.bas`：Word VBA 的 `.bas` 导入使用系统 ANSI 编码。中文 Windows 的 GBK 文件可以导入，但非中文系统会乱码；UTF-8 无 BOM 会乱码，UTF-8 BOM 可能导致导入失败。ASCII 英文 `.bas` 是最稳的分发方式，中文用户用复制粘贴。

## 测试矩阵

在 Windows 上的 Microsoft Word 16.0 中，对打包后的英文 `.bas` 和中文源码（转 GBK 测试副本）执行：

1. 已有空下一段：目标 x=52.4 → 52.4，上一行长度不变。
2. 没有下一段：自动补网格行，目标 x=52.4 → 52.4，无 4608。
3. 下一段是普通正文：插入专用注释行，原正文保留在第三段，目标 x=21.2 → 21.2。
4. 同一行第二个注释：目标 x=21.2 → 21.2，右侧「学生」保持 52.4，改写标记为 True，行数仍为 1。
5. 旧版缩进行检测分支：代码检查首行缩进并提示；未在自动化中触发 MsgBox（会阻塞），但条件与提示文案在源码中可审查。

未测试：WPS、Word for Mac、多栏、表格内、竖排、极长注释、混合半角比例字体。

## 未来可改进

- 可选的表格导出：把网格行转换成“原文/注释”两行表格。
- 可配置的网格列数/宽度；不同页面尺寸/分栏。
- 更细的半角宽度处理（按字符宽度累计，而不是仅找最近边界）。
- WPS 兼容层测试与降级路径。
- 英文/中文/日文 UI 字符串集中管理。
- 自动恢复插入模式（需要事件处理，当前为避免副作用未实现）。

## 非目标

- 不做机器翻译、假名注音或词典查询。
- 不修改日文原句内容。
- 不替代正式排版软件；大量逐词对照请用表格或 LaTeX 等工具。
